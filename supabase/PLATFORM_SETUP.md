# إعداد مشروع University Platform الموجود

هذا الدليل يكمل على مشروع Supabase المخصص للمنصة الذي أنشأته بالفعل؛ **لا تنشئ مشروعاً جديداً ولا تكرر الإعداد**.

## قبل التنفيذ
- استخدم مشروع Supabase المخصص لإدارة المنصة والمحتوى.
- لا تستخدم مشروع الخزنة المالية.
- لا تستخدم مشروع University Results الخاص بنتائج الطلاب؛ يجب أن يظل منفصلاً دون أي تعديل.

## ما الذي تنشئه الهجرة؟
- حسابات مسؤولي المنصة وصلاحياتهم في `platform_admins`.
- محتوى المنصة (محاضرات، تخصصات، مواد، أخبار، امتحانات، واجبات، إشعارات، جداول، اقتراحات) في `platform_content`.
- سجل تدقيق للإضافات والتعديلات والحذف في `platform_audit_logs`.
- مساحة ملفات خاصة `platform-files` للمحاضرات والمرفقات.
- سياسات RLS تمنع التعديل إلا للمسؤولين النشطين.

## خطوات التفعيل من حيث توقفت
1. افتح مشروع Supabase الموجود والمخصص للمنصة فقط.
2. افتح SQL Editor ونفّذ محتوى الملف `supabase/migrations/202611150001_platform_admin.sql` مرة واحدة فقط. إذا كنت نفّذته سابقاً، لا تعِد تشغيله؛ أخبرني لنراجع حالة الجداول.
3. أنشئ أول مستخدم من Authentication إذا لم يكن موجوداً بالفعل، ثم انسخ UUID الخاص به.
4. نفّذ أمر bootstrap الموجود في نهاية ملف SQL بعد استبدال UUID، مرة واحدة فقط.
5. زوّد إعدادات الواجهة بـ Project URL و publishable/anon key العامين للمشروع نفسه في `platform-config.js`.

## الأمان
- لا تضع `service_role` key في ملفات الموقع أو GitHub، ولا ترسله في المحادثة.
- مفتاح `publishable/anon` عام ومخصص للواجهة.
- لا تنفّذ أي SQL في مشروع النتائج أو الخزنة المالية.

## ما لم يُفعّل بعد
تبقى تهيئة `platform-config.js` ونشر Edge Function `invite-platform-admin` واختبارات الدخول والنشر. لا تعتبر اللوحة منشورة أو جاهزة للاستخدام العام قبل إكمال هذه الخطوات.
